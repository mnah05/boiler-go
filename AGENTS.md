# AGENTS.md

## Commands

```bash
make dev          # Start PostgreSQL + Redis via Docker
make dev-down     # Stop Docker containers
make api          # Run API server (requires running infra)
make worker       # Run background worker (requires running infra)
make test         # Run tests with race detection
make sqlc         # Regenerate sqlc code after changing sql/ queries or schema
make migrate-up   # Run DB migrations (reads DATABASE_URL from .env)
make migrate-down # Rollback one migration
```

## Startup Order

1. `make dev` — start infrastructure
2. `make migrate-up` — apply schema
3. `make sqlc` — regenerate query code if SQL changed
4. `make api` / `make worker`

## Architecture

- **Two binaries**: `cmd/api` (HTTP server) and `cmd/worker` (Asynq job consumer)
- **Module name**: `boiler-go`
- **Router**: go-chi/chi v5
- **DB driver**: pgx/v5 with sqlc-generated query code in `internal/repository/db/`
- **Job queue**: Asynq (Redis-backed), with shared task types in `internal/tasks/` and queue config in `internal/queue/`
- **Config**: `internal/config` loads all settings from env vars (caarlos0/env); no `.yaml` config files

## Code Generation

- `internal/repository/db/` is **auto-generated by sqlc** — do not edit these files directly
- Edit SQL in `sql/schema.sql` and `sql/queries/`, then run `make sqlc`
- Migrations live in `migrations/`; add new ones with `make migrate-create name=description`

## Key Conventions

- Logging uses `pkg/logger` (zerolog). Get a request-scoped logger via `logger.FromChiContext()` inside handlers
- Request IDs flow from HTTP handlers into worker tasks via Asynq payload for end-to-end tracing
- Error responses use a shared envelope: `{"error":"code","message":"...","details":[...]}` — see `internal/handler/response.go`
- Rate limiting skips `/health` and `/worker/health` endpoints
- 1MB global body size limit on all non-health routes
- No test files exist yet — when adding tests, run `make test` (which runs `go test -race ./...`)

## Env & Config

- Copy `.env.example` to `.env` before running locally
- All config is env-var-driven; defaults are in `internal/config/config.go` struct tags
- `LOG_OUTPUT=file` or `both` requires `LOG_FILE` to be set; log files are written with 0600 permissions

## Database

- Pool settings are configurable via env vars (`DB_MAX_CONNS`, `DB_MIN_CONNS`, etc.)
- `internal/repository/pool` is a singleton guarded by `sync.RWMutex`; call `pool.Open(ctx, cfg)` then `pool.Get()`
- Transaction helper: `repo.NewTxManager(pool, log)` provides `Execute(ctx, func(q *db.Queries) error)`
- All repo methods log query duration automatically via `baseRepo`

## Known Gaps (from plan.md)

- No test coverage yet
- Worker shutdown error handling needs improvement
- Request contexts have no DB timeouts — consider adding `context.WithTimeout` in handlers
